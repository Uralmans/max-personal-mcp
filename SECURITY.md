# Безопасность и конфиденциальность

[English](SECURITY.en.md)

## Модель доверия

Проект рассчитан на один доверенный компьютер и одного владельца аккаунта. MCP-клиент, имеющий доступ к `docker exec`, может читать переписку и отправлять сообщения. Правило «отправлять только по просьбе пользователя» задаётся описаниями инструментов и инструкциями MCP; отдельного подтверждения каждой отправки сервер не реализует. Не подключайте недоверенных агентов или удалённых пользователей.

Порт опубликован только на loopback. Не меняйте привязку на `0.0.0.0`, не публикуйте Docker socket и не используйте эту конфигурацию как общий интернет-сервис. Root внутри Linux-контейнера не используется, но доступ к Docker на хосте сам по себе является привилегированным.

## Где находятся секреты

| Данные | Место |
| --- | --- |
| Сессия MAX, отметка авторизации, ключ MCP | Docker volume `/data` |
| Пароль при входе | Память процесса на время запроса; приложение не пишет его на диск |
| Прокси с учётными данными | Ваш локальный `.env` или окружение |
| Временные исходники и квитанции | `transfer/`, по умолчанию внутри checkout |
| Скачанные вложения | `/data/downloads` |
| Приватная копия для отправки | `/data/uploads`, удаляется при штатном завершении |

Не экспортируйте том, QR-код, HAR, полный вывод профиля/истории или вложение с персональными данными в issue. История MAX может содержать подписанные URL и токены файлов. Сервис исключает удалённое содержимое из некоторых сообщений об ошибках, но это не гарантия обезличивания любого стороннего лога или traceback.

Сессия MAX и Bearer-ключ — разные секреты: Bearer защищает локальный MCP, сессия авторизует клиента в MAX. При утечке сессии отзовите устройство в MAX; удаление одного MCP-ключа её не отзывает. Пересоздание контейнера само по себе не удаляет сохранённые секреты из тома.

## Что защищает приложение

- Host/Origin-проверки для локальной страницы и Bearer для MCP.
- `no-store`, запрет встраивания страницы и передача пароля через локальный POST.
- Неофициальный клиент MAX проверяет TLS; CONNECT-помощник TLS не расшифровывает.
- Явная папка передачи и проверка файлов без перехода по ссылкам; отдельная копия фиксирует отправляемые байты.
- `.gitignore`, список разрешённых файлов Docker и проверка публикуемых файлов в CI.

HTTP-страница входа локальная. Это не защита от вредоносного ПО или другого пользователя с доступом к Docker/вашему аккаунту ОС. В конфигурации нет многопользовательской изоляции, квот диска или ограничения числа параллельных отправок. Учитывайте свободное место и не запускайте массовые загрузки.

## Перед коммитом

```sh
python3 scripts/check_public_files.py
# Дополнительная независимая проверка, если установлен Gitleaks:
gitleaks dir . --redact
```

`.gitignore` не удаляет уже закоммиченные файлы. Проверяйте `git diff --cached` и историю. Если секрет уже попал на GitHub, сначала отзовите/замените его, затем очищайте историю. Не публикуйте реальные сессии для воспроизведения ошибки; используйте фиктивные данные.

## Сообщить о проблеме

Не создавайте публичный issue с секретами или доказательством, содержащим личную переписку. Если в репозитории доступна приватная вкладка Security → Report a vulnerability, используйте её. Иначе отправьте через доступный контакт владельца только краткое описание без секретов; не предполагайте наличие отдельной службы безопасности или гарантированного срока ответа.
