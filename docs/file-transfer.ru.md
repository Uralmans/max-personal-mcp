# Передача файлов

[English](file-transfer.en.md) · [README](../README.md)

## 1. Подготовка

Перед отправкой должны быть понятны файл и получатель из прямого поручения пользователя. Для собственного «Избранного» проверьте чат `0` через `get_chat`; для других чатов используйте подтверждённый ID.

```sh
python3 scripts/transfer.py stage /path/to/report.zip
```

PowerShell:

```powershell
py -3 scripts/transfer.py stage 'C:\path\report.zip'
```

Скрипт создаёт отдельное UUID-задание в `transfer/pending`, копирует файл и вычисляет SHA-256. Разные файлы с одинаковыми именами получают разные подпапки. В ответе будут `job`, `bytes`, `sha256` и `container_path`. Оригинал не меняется.

По умолчанию корень — `transfer` в репозитории. Для другого места задайте **абсолютный** `MAX_TRANSFER_DIR` одновременно в окружении скрипта и Compose, прежде чем запускать контейнер. Пример для POSIX: `export MAX_TRANSFER_DIR="$HOME/.local/share/max-mcp-transfer"`. В PowerShell: `$env:MAX_TRANSFER_DIR = Join-Path $HOME 'max-mcp-transfer'`.

## 2. Отправка через MCP

Вызовите `send_file` с аргументами:

```json
{
  "chat_id": "0",
  "file_path": "/transfer/<job>/000/report.zip",
  "caption": "Requested document"
}
```

Замените `<job>` реальным идентификатором из `stage`. `reply_to` — необязательный строковый ID сообщения; подпись до 4000 символов, форматирование соответствует PyMax. Расширять монтирование до всего диска не нужно.

Инструмент допускает обычные файлы от 1 байта до 2 000 000 000 байт. Создаёт приватную неизменяемую копию внутри Docker volume; для неё нужны свободное место и время. Символьные/жёсткие ссылки, `..`, каталоги и специальные файлы отклоняются.

`accepted_by_max` означает, что MAX вернул ID сообщения. Это ещё не проверка скачивания получателем. В ответе также есть размер и SHA-256 отправленных байтов.

## 3. Проверка и очистка

Проверьте историю через `read_messages`: сообщение с нужным ID, имя и размер вложения. Для проверки исходных байтов используйте `download_file` с ID файла, сообщением, именем и ожидаемым размером из истории; сравните SHA-256. Подписанные URL и токены вложений не публикуйте.

После проверки:

```sh
python3 scripts/transfer.py finish --job <job> --chat-id 0 --message-id <message-id>
```

Подтверждение запишется в `transfer/receipts`, временная копия задания удалится. Скрипт доверяет вашей проверке и не обращается к MAX. При проверочном скачивании дополнительно удалите файл из `/data/downloads` после сравнения.

## Сбой и срок хранения

При тайм-ауте или неизвестном результате сначала проверьте историю; не отправляйте файл повторно вслепую. Внутренняя копия `/data/uploads/max-send-*` удаляется при обычном завершении, исключении и штатной отмене; аварийное завершение процесса может оставить её на диске. Копия на хосте остаётся до `finish`, `cancel` или очистки.

```sh
python3 scripts/transfer.py status
python3 scripts/transfer.py cancel --job <job>
python3 scripts/transfer.py sweep
```

`sweep` удаляет управляемые задания старше 24 часов, как и `stage` перед новой подготовкой. Фонового таймера нет. Не удаляйте всю общую папку вручную: её могут использовать другие задания. Квитанции содержат локальные пути и ID чатов; они тоже исключены из Git.

MCP-обёртка не повторяет отправку после неизвестного сетевого результата. PyMax отдельно может повторить запрос на явный ответ сервера `attachment.not.ready`; это другой случай.
