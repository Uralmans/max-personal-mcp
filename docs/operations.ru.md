# Эксплуатация

[English](operations.en.md) · [README](../README.md)

## Запуск и вход

1. Клонируйте репозиторий; выполните `python3 scripts/transfer.py status`, чтобы создать папку передачи.
2. При необходимости скопируйте `.env.example` в `.env` и задайте прокси. Храните `.env` локально.
3. Запустите `docker compose up -d --build`.
4. Откройте `http://127.0.0.1:9030/`, запросите QR-код и подтвердите вход в приложении MAX на телефоне через раздел устройств. Названия пунктов зависят от версии MAX.
5. Если нужен пароль, введите его на локальной странице, затем дождитесь подключения.

На Windows команда Python может называться `py -3` или `python`. Установите Docker Desktop с Linux-контейнерами. Команды с `$PWD` ниже рассчитаны на POSIX shell; для PowerShell путь монтирования передавайте как `"${PWD}/tests:/tests:ro"`.

Контейнер имеет фиксированное имя `max-mcp`. Если оно уже занято, сначала определите, какому проекту принадлежит существующий контейнер. Не удаляйте рабочий сервис или его том ради запуска второй копии.

## Сессия

Сессия, отметка авторизации и ключ MCP сохраняются в именованном томе `max-session`. Compose добавляет к его имени префикс проекта. Остановка контейнера сессию сохраняет. `docker compose down -v` удаляет её: не используйте эту команду, если хотите сохранить вход.

После перезапуска сервис пытается восстановить вход. Если MAX отозвал сессию, потребуется новый QR. Отозвать подключение можно через список устройств MAX. Пароль 2FA передаётся MAX и не записывается этим приложением; сессия даёт доступ к аккаунту без повторного ввода пароля, поэтому защищайте сам том.

## Проверки

```sh
docker compose ps
docker exec max-mcp python /app/probe.py
```

`/health` подтверждает доступность сервиса, но не вход в аккаунт. Только `account_status.authorized=true` подтверждает активное подключение. `probe.py` проверяет реальный stdio-мост, список инструментов и доступ к аккаунту без печати содержимого профиля или чатов. Вызов не отправляет сообщений.

`list_chats` использует кеш login/sync, который может быть неполным. Пустой результат поиска не доказывает отсутствие чата. Чат «Избранное» может не иметь названия; для ID `0` проверьте сведения через `get_chat`.

## Прокси и сеть

`MAX_PROXY` передаётся PyMax, а скачивание вложений использует тот же прокси. Совместимость схемы и авторизации зависит от библиотек; проверьте выбранный прокси в своей среде. Не публикуйте URL, если он содержит логин или пароль.

Если QR/соединение не появляются, проверьте DNS и доступ компьютера и контейнера к MAX. После изменения `.env` выполните `docker compose up -d`. Сервис не меняет системный VPN или маршруты автоматически.

В `app/direct_proxy.py` есть **необязательная экспериментальная утилита для macOS**, не запускаемая Compose. Она создаёт CONNECT-прокси на `127.0.0.1:19031` с привязкой к интерфейсу `MAX_DIRECT_INTERFACE` (по умолчанию `en0`). Требует путь `MAX_DIRECT_TOKEN_FILE` к созданному вами секрету. Разрешены только `max.ru`/`oneme.ru` и их поддомены, порт 443 и глобальные IPv4-адреса. TLS не расшифровывается. Утилита не поддерживает Windows/Linux; не запускайте её без понимания маршрута и способа доступа контейнера к хосту.

## Обновление и откат

Перед обновлением сохраните текущий тег/образ приложения. Переключитесь на нужный Git-тег или commit и выполните `docker compose up -d --build`. Сохраняйте тот же Compose project name, чтобы не создать другой том вместо прежнего.

При откате вернитесь на прежний commit и пересоберите контейнер с тем же томом. Сессия не мигрируется этим проектом; совместимость её формата с другой версией PyMax нужно проверять отдельно.

После пересоздания контейнера stdio-подключение клиента может закрыться. Переподключите MAX MCP или начните новый чат.

## Ограничения

Нет звонков, удаления/редактирования сообщений, многопользовательских ролей или обещания полной эквивалентности официальному приложению. ID передавайте в аргументах MCP строками: большие числа могут потерять точность в JavaScript. Внутри ответа PyMax ID могут быть числами — учитывайте это при собственной обработке JSON.
